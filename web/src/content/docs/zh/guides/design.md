zoetrope 只有一个难题，它的大多数设计都由此而来：

> 从一份**未文档化、只增不改、只有部分时间戳、且分散在多个文件**的 transcript
> 中——其中很多事情**你无法知道它何时结束**——重建一个忠实的、可导航的、
> 可直播可回放的 Claude Code 会话视图。

答案的形状是**事件溯源（event sourcing）**：把 transcript 当作只增不改的事件日志，
其余一切都从它推导。

## 模型是一个投影

zoetrope 从不原地修改会话模型。它把事件日志**折叠（fold）**成一个**投影**，而这个
投影是事件*集合*的纯函数，与事件到达的顺序无关。每次更新都是**幂等的**（重放一个
事件是空操作）且**可交换的**（两个事件以任意顺序都到达同一状态），因此折叠是**顺序
无关的**：任何到达顺序都收敛到同一个投影。有三件事依赖这一点：

- **多文件合并。** 主 transcript、子 agent 文件和工作流 journal 是三份按时间戳交错
  的独立日志。一个子 agent 的结果可能先于它的派生被折叠。
- **时间旅行。** 回退到过去会从日志的一个前缀（`events[0..cursor]`）重建投影，所以
  它必须精确落在“播放到那里”本来会产生的那份状态上。这是会话版的时间旅行调试。
- **直播与回放。** 同样的事件以预排序（回放）或到达序（直播）到来，两者必须收敛到
  同一个投影。

一个**基于性质的测试**会打乱一条真实事件流，断言每次最终投影都相同。

一个推论：**派生状态是可逆的。** 投影是从当前事件集重新计算的，而不是累加的，所以
一个已经断言“完成”的汇总会在矛盾事件（迟到的子项、恢复的工具）到达的瞬间回退。
它永远不是一次写定。

## 双时钟

每个随时间变化的量都活在两个时钟之一上，且两者永不混淆。

- **内容时间（content-time）**是播放头：会话自身的逻辑时钟，由事件时间戳推进。
  **领域状态**从这里读取（agent 的状态、一个工具调用是否仍在进行、一次调用属于哪
  个 run），所以无论你怎样定位到某个播放头，它在那里都是确定的。
- **呈现时间（presentation-time）**是墙钟，只在你播放时前进。**视图状态**在这里：
  渐隐、镜头滑移、脉冲。它只向前，且不会在定位时重放。

领域状态读内容时间、视图状态读墙钟，这让被定位到的那一帧精确渲染当时为真的东西，
确定性的，没有墙钟渗漏进模型。

## 事实优先于推导

日志很少记录某件事*结束了*，所以投影用**计算出来的状态**填补空隙。让这一点保持
诚实的不变量是：

> 只在没有事实的地方推导，且永远不让推导覆盖模型中已有的事实。

两种情况承担了大部分重量：

- **派生确认不是完成。** "Async agent launched successfully" 是一个句柄，不是结果。
  子 agent 随后要在自己的侧链里运行数分钟。真正的完成是一个明确的终止事件
  （task notification 或工作流 journal 的 result），它会钉住 agent，让基于时间的
  启发式无法将它复活。
- **未决的工具调用就是事实。** 一个进行中的调用是 agent 正在工作的硬证据，优先级
  高于任何“空闲了 N 秒”的推断。所以一个慢工具的指示器不会在它的结果落地之前消失。

一切计算出来的东西（活跃窗口、分组汇总、无时间戳事件的排序）都必须是当前事实的
可逆函数、且填补的是真实的空隙。任何覆盖模型中已有事实的行为都是 bug。

## 一条时间线上的时间旅行

直播和回放不是两种模式。它们是同一个时间位移的模型：一份按时间戳排序的事件列表
和一个播放头。唯一的区别是右**边缘**是固定的（已结束的文件）还是仍在生长（正在被
写入的会话）。

- **决定“钉住还是前进”的是边缘，不是模式标志。** 在边缘之后播放头按节奏前进，并
  以对数曲线压缩空闲段，所以五分钟的等待读起来仍然比五秒的长（<kbd>s</kbd> 切换
  实时）。在边缘上它钉住，把新到达的内容流进来。两种情况下 <kbd>space</kbd> 都从
  播放头继续，回拖过的直播会话会追上边缘然后跟随。
- **进度条按事件索引，不按墙钟。** 真实会话是爆发式工作然后空闲数小时，线性时间轴
  会把工作埋进一条缝里。轨道是铺在事件区间上的工具活跃度火花线。
- **传输状态是推导的，不是存储的。** 直播、播放、已暂停、回看、空闲都是从播放头
  相对边缘的位置和新内容的新鲜度算出来的。它是一台状态机，不是你设置的模式。

## 一个核心，两个前端

最底下是**可移植核心**：领域模型、直播/回放时间线、流程图投影、渲染和 transcript
解析器。它不做 IO，可为任何目标编译，包括 WebAssembly。两个刻意做薄的前端架在它
上面，每个一个 crate。

- **`zoetrope`**——你安装的 crate，核心就住在这里。核心之上它加了**终端前端**：
  文件 tail 循环、终端生命周期和键盘输入。这些引入 `tokio` 和文件系统，所以放在
  一个默认开启、对其他目标关闭的 `native` feature 之后。
- **`zoetrope-web`**——**浏览器前端**，在
  [`web/wasm/`](https://github.com/furkankly/zoetrope/tree/main/web/wasm)。它以默认
  feature 关闭的方式依赖核心，加上 [ratzilla](https://github.com/ratatui/ratzilla)
  的 WebGL2 后端和一层薄薄的事件转换。浏览器没有文件系统，所以字节被直接交给同一
  台引擎——无论来自内置演示、上传的 transcript，还是经 File System Access API 打开
  的文件夹。它作为本站的 [`/app`](/app) 路由部署，永远不被安装。

所有 IO 都是本地的。输入是你的文件系统，或在浏览器里是你递给它的字节，且依赖树里
任何地方都没有 HTTP 客户端。
